# GABBY 쇼핑몰 (Next.js)

패션 쇼핑몰입니다. Next.js(App Router) + TypeScript + Prisma + Neon(PostgreSQL), Vercel 배포를 기준으로 만들었습니다.
상품 이미지는 DB에 저장하고, 결제는 아직 연결하지 않았습니다(주문은 "주문 접수" 상태로 저장).

## 실행

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # 배포용 빌드
```

## 배포와 처음 설정

1. GitHub 저장소를 Vercel에서 Import합니다. (Framework는 Next.js로 자동 선택)
2. Vercel Storage에서 **Neon**을 설치해 프로젝트에 연결합니다. `DATABASE_URL`, `DATABASE_URL_UNPOOLED`가 자동으로 들어갑니다.
3. 컴퓨터에서 실행하려면 `.env.example`을 `.env`로 복사해 값을 채웁니다. (`.env`는 GitHub에 올리지 마세요)
4. **관리자 계정 만들기:** Neon SQL Editor에서 `prisma/admin-setup.sql`의 두 문장을 한 문장씩 실행합니다. (아이디 `admin` / 비밀번호 `admin`)
5. **DB 변경은 배포할 때 자동으로 적용됩니다.** 빌드(`npm run build`)가 시작될 때 `scripts/db-setup.mjs`가 `prisma/setup-statements.json`의 명령(테이블·컬럼 만들기)을 실행합니다. "이미 있으면 건너뛰기" 명령만 쓰므로 기존 데이터는 지워지지 않고, DB에 접속하지 못해도 빌드는 멈추지 않으며 로그(`[db-setup]`)만 남깁니다. 같은 일을 **관리자 > DB 설정 > 테이블 만들기** 버튼으로 직접 실행할 수도 있습니다. (새 테이블·컬럼이 필요한 기능을 만들 때는 `prisma/schema.prisma`와 `prisma/setup-statements.json` 두 곳에 함께 추가하세요.)
6. **관리자 > 관리자 계정**에서 비밀번호를 바꿉니다. `admin`/`admin`은 누구나 추측할 수 있습니다.

> 배포 직후 화면이 새 컬럼 때문에 오류를 내면 Vercel 빌드 로그에서 `[db-setup]`을 검색해 DB 변경이 적용됐는지 확인하세요. 로그인과 관리자 화면(DB 설정)은 새 컬럼이 없어도 열리도록 만들어 두었으니, 관리자 화면의 `테이블 만들기` 버튼으로 직접 적용할 수 있습니다. 오류가 나면 **관리자 > 오류 기록**에서 내용과 오류 번호를 찾을 수 있습니다.

### 환경 변수 (선택)

| 이름 | 용도 |
|---|---|
| `RESEND_API_KEY`, `EMAIL_FROM` | 이메일 발송(비밀번호 찾기, 주문 알림). 없으면 메일만 건너뜁니다. |
| `SITE_URL` | 메일 링크에 쓰는 사이트 주소 (예: https://내사이트.com) |
| `HERO_IMAGE_URL` | 메인 화면 큰 배경 사진 주소 (없으면 부드러운 색 배경). 예: `/api/product-image/이미지번호` 또는 `https://...` |
| `INSTAGRAM_URL`, `YOUTUBE_URL`, `KAKAO_URL` | 푸터의 소셜 링크 (넣은 것만 보입니다) |
| `ADMIN_EMAIL` | 새 주문·고객 주문 취소를 받을 관리자 이메일 |
| `KAKAO_REST_API_KEY` (`KAKAO_CLIENT_SECRET`) | 카카오 로그인 (아래 설정 방법 참고) |

### 카카오 로그인 설정

1. [카카오 개발자](https://developers.kakao.com)에서 앱을 만들고 **카카오 로그인**을 켭니다.
2. **Redirect URI**에 `https://내사이트/api/auth/kakao/callback`을 등록합니다. (주소가 한 글자라도 다르면 로그인이 되지 않습니다. `SITE_URL`을 설정해 두면 그 주소를 씁니다.)
3. 동의 항목에서 닉네임(필수), 이메일(선택)을 설정합니다. 이메일 동의는 카카오 쪽 앱 심사·설정이 필요할 수 있어 확인해 주세요.
4. 앱 키의 **REST API 키**를 `KAKAO_REST_API_KEY`로 Vercel 환경 변수에 넣고 Redeploy합니다. (보안 설정에서 Client Secret을 켰다면 `KAKAO_CLIENT_SECRET`도 넣습니다.)
- 카카오로 처음 로그인하면 회원이 자동으로 만들어집니다(아이디 `kakao_번호`). 이미 같은 이메일의 일반 회원이 있어도 자동으로 합치지 않습니다. 휴대전화는 받지 못해 비어 있으므로, 회원 정보 수정에서 입력해야 합니다.

## 기능

**고객**
- 카테고리(WOMEN, BEST, NEW): 하위 분류(아우터, 상의, 하의, 드레스, 셋업, 신발 / 악세서리) 필터, 정렬(신상품순, 인기순, 낮은가격순, 높은가격순), 페이지, 실제 상품 수
- 상품 상세: 상세 내용(글·이미지), 배송·교환·반품 안내, 사이즈표, 이미지 여러 장(작은 사진을 누르면 큰 이미지가 바뀜), 색상·사이즈(상품마다 다름, FREE 하나만도 가능)·수량 선택, 장바구니, 바로 구매, 관심 상품, 후기(사진 포함), 품절·재고 표시, 재입고 알림 신청, 할인율 적용 가격, 배송비 안내
- 검색, 장바구니, 주문/결제(주소 검색, 쿠폰, 적립금), 주문 완료, 주문 내역·상세(택배사·운송장·판매자 안내)
- 회원: 가입, 로그인(시도 횟수 제한), 카카오 로그인, 아이디·비밀번호 찾기, 회원 정보 수정, 배송지 관리(저장·기본 배송지, 주문할 때 선택), 관심 상품, 쿠폰, 적립금, 취소·반품·교환 신청, **회원 탈퇴**(개인정보 삭제, 주문 기록은 보관)
- 주문 취소: 배송 준비 전(주문 접수·결제 완료)에는 주문 상세에서 **취소 사유를 적고 바로 취소**합니다(회원, 비회원 모두). 사유는 관리자 주문 화면·목록·대시보드에 보이고, 고객에게 취소 확인 메일, 관리자(`ADMIN_EMAIL`)에게 사유가 담긴 알림 메일이 갑니다. 배송 준비 중에는 취소 요청, 배송 시작 후에는 반품·교환을 신청합니다.
- 비회원: 상품 상세의 `BUY NOW`로 주문, 이름+휴대전화로 주문 조회(배송지·연락처는 일부 가려서 표시)
- 게시판: 후기(구매한 상품만, 사진 3장까지, 20자 이상 500원·사진 후기 1,000원 적립), Q&A(비밀글), 공지사항
- 오류가 나면 안내 화면(오류 번호 표시)이 보이고, 404 화면이 따로 있습니다.
- 전화번호는 입력하면 하이픈(-)이 자동으로 들어갑니다.

**관리자 (`/admin`)**
- 대시보드, 통계(최근 7·30·90일 매출·주문·취소·신규 회원·일별 그래프·인기 상품) 와 엑셀(CSV) 내보내기(주문, 회원, 상품, 취소·반품·교환), 주문/배송 관리(상태·택배사·운송장·고객에게 보이는 메모, 상태 변경 시 이메일 알림), 회원 관리
- 상품 관리: 상세 내용 편집(글과 이미지를 원하는 순서로), 사이즈표 입력(양식 불러오기), 추가·수정·삭제, 정가·할인율, 대표 이미지 + 추가 이미지 5장(DB 저장), 색상 옵션(최대 8개, 재고는 사이즈별로만 관리), 사이즈별 재고, 품절 처리, WOMEN 기본 + BEST·NEW 표시, 하위 분류
- 후기·문의(답변)·공지 관리, 취소·반품·교환 처리, 쿠폰 만들기, 재입고 알림 신청자 수 확인, **오류 기록**(자동 수집, 새 오류 이메일 알림, 오류 번호 검색), DB 설정

## 규칙

- **할인가**는 정가에서 할인율만큼 자동 계산(10원 단위 아래 버림)하고, 장바구니·주문에 적용됩니다.
- **배송비**는 상품금액(할인가 합계)이 70,000원 이상이면 무료, 미만이면 3,000원입니다(`lib/orders.ts`의 `FREE_SHIPPING_MIN`, `SHIPPING_FEE`에서 바꿉니다). 쿠폰·적립금과 상관없이 상품금액으로 정합니다.
- **사이즈**는 상품마다 정합니다(S/M/L, FREE 하나만, 직접 추가 가능). **재고**는 사이즈별로 관리합니다. 칸을 비우면 무제한, 0이면 품절입니다. 주문이 저장될 때 줄고, 주문을 취소하면 되돌아갑니다. 품절이던 상품이 다시 살 수 있게 되면 **재입고 알림** 신청자에게 이메일이 갑니다(이메일 서비스 설정 시).
- **적립금**은 배송 완료 시 결제 금액(배송비 제외)의 1%(`lib/orders.ts`의 `POINT_RATE`)입니다. **쿠폰**은 주문당 1개입니다. 주문을 취소하면 사용한 적립금·쿠폰은 돌아가고 받은 적립금은 회수됩니다.
- **회원 탈퇴:** 비밀번호(카카오 회원은 "탈퇴" 입력)로 확인하고, 진행 중인 주문·신청이 없을 때만 가능합니다. 회원 정보를 "탈퇴한 회원"으로 바꾸고 배송지·장바구니·관심 상품·쿠폰·적립금·후기·문의를 지웁니다. 주문 기록은 법령상 보관이 필요해서 남깁니다(보관 기간과 삭제 방법은 개인정보처리방침에 맞게 정해 주세요).
- **횟수 제한:** 로그인(같은 아이디 5번, 같은 접속지 20번 실패 시 15분), 아이디 찾기, 비밀번호 재설정 메일 요청, 비회원 주문 조회·주문
- **로그인이 필요한 화면**은 `middleware.ts`의 `PROTECTED` 목록(쿠키 확인)과 각 화면의 `requireUser()`/`requireAdmin()`(DB 확인)으로 두 번 확인합니다. 새 보호 화면은 두 곳에 모두 추가하세요.
- 이미지는 올리기 전에 브라우저에서 가로 1200px 이하로 줄이고, 서버는 2MB까지 받습니다. 무료 DB 용량을 쓰므로 사진을 아주 많이 올릴 계획이라면 별도 파일 저장소를 고려하세요.

## 판매 시작을 위한 기능

- **무통장입금:** 지금 결제 수단은 무통장입금만 있습니다(결제 서비스를 연결하면 `lib/business.ts`의 `PAYMENT_METHODS`에 추가). 주문하면 "입금 대기"가 되고 입금 계좌·입금자명·기한(72시간)이 주문 완료 화면과 메일에 나옵니다. 관리자가 주문 화면에서 **입금 확인**을 누르면 "결제 완료"로 바뀌고 고객에게 메일이 갑니다. 기한이 지난 미입금 주문은 하루 한 번 자동으로 취소됩니다(환경 변수 `CRON_SECRET`이 있어야 하고, `vercel.json`의 crons가 `/api/cron/daily`를 부릅니다).
- **사업자 정보·계좌·약관:** 사업자 정보, 입금 계좌, 고객센터는 `lib/business.ts` 한 곳에서 바꿉니다(푸터, 약관, 안내 문구가 같이 바뀜). 이용약관(`/terms`)과 개인정보처리방침(`/privacy`)은 `lib/legal.ts`의 **템플릿**입니다. 법률 검토를 거친 문서가 아니니 꼭 확인하고 고쳐서 쓰세요.
- **검색 노출:** `sitemap.xml`, `robots.txt`, 파비콘, 공유 이미지, 상품 구조화 데이터가 자동으로 만들어집니다. `SITE_URL`을 설정해 두세요.
- **이미지 속도:** 목록·카드·후기 사진은 `?w=240|480|800`으로 줄인 가벼운 이미지를 씁니다(`sharp`, 실패하면 원본).
- **휴대폰 상품 상세:** 구매 버튼(관심 상품·장바구니·바로 구매)이 화면 아래에 붙어 있습니다.
- **FAQ**(`/faq`, 관리자에서 관리), **카카오톡 상담 버튼**(환경 변수 `KAKAO_URL`을 넣으면 보임), **공유하기**, **최근 본 상품**.
- **배송:** 택배사를 고르면 고객 화면과 메일에 배송 추적 링크가 생깁니다(무료 조회 서비스 tracker.delivery 연결). **관리자 > 운송장 일괄 입력**에서 여러 주문의 운송장을 한꺼번에 저장하고(엑셀에서 복사해 붙여넣기도 가능) 발송 메일을 보내며, 주문서·송장을 인쇄할 수 있습니다.
- **회원 관리:** 관리자가 회원 상세에서 적립금을 지급·차감하고 쿠폰을 직접 줄 수 있으며, 회원의 주문·적립금·쿠폰을 한눈에 봅니다. 쿠폰을 "회원가입 때 자동 지급"으로 만들면 새 회원(카카오 포함)에게 자동으로 갑니다. **회원 등급**(일반·실버·골드)은 누적 구매 금액에 따라 적립률이 달라집니다(`lib/grades.ts`).

## 속도와 DB 공간

- 목록·카드·장바구니·검색은 필요한 컬럼만 읽어서(상품 상세 내용 같은 큰 글은 읽지 않음) DB에서 가져오는 양이 적습니다. 자주 쓰는 조회에는 색인(index)을 추가했습니다(배포할 때 자동 적용).
- 같은 요청 안에서 로그인 정보와 상품 정보는 한 번만 조회하고, 상품 이미지 요청은 미들웨어를 거치지 않으며 브라우저에 오래 저장됩니다.
- 이미지는 DB에 저장하므로 시간이 지나면 공간을 차지합니다. **관리자 > DB 설정 > DB 정리**에서 저장된 이미지 용량을 보고, 사용하지 않는 이미지와 오래된 기록을 지울 수 있습니다. (한 달에 한 번 정도)

## 교환·반품 안내와 사이즈표

- 배송·교환·반품 문구는 `lib/policy.ts`에 있고(상품 상세와 `/shipping-return` 화면이 같이 씀), 대부분의 쇼핑몰에서 쓰는 일반적인 내용입니다. **금액(왕복 배송비), 기간, 반품 주소, 고객센터, 환불 기간은 판매자 정책에 맞게 직접 바꾸고, 법적으로 맞는지 꼭 확인하세요.**
- 상품 상세의 아래쪽은 위에서부터 `상품 정보(관리자가 넣은 글·이미지)` → `배송·교환·반품` → `사이즈표` → `후기` 순서입니다. 내용이나 표를 넣지 않은 상품에는 그 구역이 보이지 않습니다.

## 디자인

메인 화면은 맨 위 흘러가는 안내 띠 → 가운데 로고가 있는 헤더(왼쪽 SHOP 메뉴, 오른쪽 회원·검색·장바구니) → 큰 히어로 → 카테고리 타일 → NEW ARRIVALS·BEST → 후기·공지 → 단정한 푸터 순서입니다.
- 문구: `app/page.tsx` 맨 위의 `HERO`, 안내 띠는 `components/Marquee.tsx`, 푸터의 사업자 정보는 `components/Footer.tsx`에서 바꿉니다.
- 색과 글꼴은 `app/globals.css`(제목은 Cormorant Garamond 계열 명조, 본문은 Noto Sans KR)에서 바꿉니다.
- 관리자 화면은 같은 사이트 안에서 별도의 단정한 글꼴로 유지됩니다.

## 폴더

| 경로 | 설명 |
|---|---|
| `app/` | 화면(페이지)과 서버 동작. `app/admin/`은 관리자, `app/actions/`는 서버 동작, `app/api/`는 이미지 업로드·표시 |
| `components/` | 공통 부품 (헤더, 푸터, 상품 카드, 폼 등) |
| `lib/` | 공통 로직 (DB, 로그인, 가격·할인, 사이즈·색상, 재고, 쿠폰, 주문 처리, 이메일, 재입고 알림, 오류 기록, 횟수 제한, 이미지 업로드) |
| `scripts/db-setup.mjs`, `prisma/setup-statements.json` | 배포할 때 DB 테이블·컬럼을 자동으로 만드는 도구와 명령 목록 |
| `instrumentation.ts` | 서버 오류를 자동으로 기록하는 연결 지점 |
| `prisma/schema.prisma` | DB 테이블 정의 |
| `prisma/admin-setup.sql` | 처음 한 번, 관리자 계정 만들기 |
| `middleware.ts` | 로그인 필요한 주소의 1차 확인 |
