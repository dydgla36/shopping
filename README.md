# GABBY 쇼핑몰 (Next.js)

패션 쇼핑몰입니다. Next.js(App Router) + TypeScript + Prisma + Neon(PostgreSQL), Vercel 배포를 기준으로 만들었습니다.
상품 이미지는 DB에 저장하고, 결제는 아직 연결하지 않았습니다(주문은 "주문 접수" 상태로 저장).

## 실행

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # 배포용 빌드
```

## 배포와 처음 설정

1. GitHub 저장소를 Vercel에서 Import합니다. (Framework는 Next.js로 자동 선택)
2. Vercel Storage에서 **Neon**을 설치해 프로젝트에 연결합니다. `DATABASE_URL`, `DATABASE_URL_UNPOOLED`가 자동으로 들어갑니다.
3. 컴퓨터에서 실행하려면 `.env.example`을 `.env`로 복사해 값을 채웁니다. (`.env`는 GitHub에 올리지 마세요)
4. **관리자 계정 만들기:** Neon SQL Editor에서 `prisma/admin-setup.sql`의 두 문장을 한 문장씩 실행합니다. (아이디 `admin` / 비밀번호 `admin`)
5. 배포된 사이트에서 로그인한 뒤 **관리자 > DB 설정 > 테이블 만들기**를 한 번 누릅니다. 필요한 테이블과 컬럼을 모두, 이미 있는 것은 건너뛰며 만들어 줍니다. **새 코드를 올릴 때마다 한 번 눌러 주세요**(이미 있으면 아무 일도 일어나지 않습니다).
6. **관리자 > 관리자 계정**에서 비밀번호를 바꿉니다. `admin`/`admin`은 누구나 추측할 수 있습니다.

### 환경 변수 (선택)

| 이름 | 용도 |
|---|---|
| `RESEND_API_KEY`, `EMAIL_FROM` | 이메일 발송(비밀번호 찾기, 주문 알림). 없으면 메일만 건너뜁니다. |
| `SITE_URL` | 메일 링크에 쓰는 사이트 주소 (예: https://내사이트.com) |
| `ADMIN_EMAIL` | 새 주문·고객 주문 취소를 받을 관리자 이메일 |
| `KAKAO_REST_API_KEY` (`KAKAO_CLIENT_SECRET`) | 카카오 로그인 (아래 설정 방법 참고) |

### 카카오 로그인 설정

1. [카카오 개발자](https://developers.kakao.com)에서 앱을 만들고 **카카오 로그인**을 켭니다.
2. **Redirect URI**에 `https://내사이트/api/auth/kakao/callback`을 등록합니다. (주소가 한 글자라도 다르면 로그인이 되지 않습니다. `SITE_URL`을 설정해 두면 그 주소를 씁니다.)
3. 동의 항목에서 닉네임(필수), 이메일(선택)을 설정합니다. 이메일 동의는 카카오 쪽 앱 심사·설정이 필요할 수 있어 확인해 주세요.
4. 앱 키의 **REST API 키**를 `KAKAO_REST_API_KEY`로 Vercel 환경 변수에 넣고 Redeploy합니다. (보안 설정에서 Client Secret을 켰다면 `KAKAO_CLIENT_SECRET`도 넣습니다.)
- 카카오로 처음 로그인하면 회원이 자동으로 만들어집니다(아이디 `kakao_번호`). 이미 같은 이메일의 일반 회원이 있어도 자동으로 합치지 않습니다. 휴대전화는 받지 못해 비어 있으므로, 회원 정보 수정에서 입력해야 합니다.

## 기능

**고객**
- 카테고리(WOMEN, BEST, NEW): 하위 분류(아우터, 상의, 하의, 드레스, 셋업, 신발 / 악세서리) 필터, 정렬(신상품순, 인기순, 낮은가격순, 높은가격순), 페이지, 실제 상품 수
- 상품 상세: 이미지 여러 장(작은 사진을 누르면 큰 이미지가 바뀜), 색상·사이즈·수량 선택, 장바구니, 바로 구매, 관심 상품, 후기, 품절·재고 표시, 할인율 적용 가격
- 검색, 장바구니, 주문/결제(주소 검색, 쿠폰, 적립금), 주문 완료, 주문 내역·상세(택배사·운송장·판매자 안내)
- 회원: 가입, 로그인(시도 횟수 제한), 카카오 로그인, 아이디·비밀번호 찾기, 회원 정보 수정, 관심 상품, 쿠폰, 적립금, 취소·반품·교환 신청
- 주문 취소: 배송 준비 전(주문 접수·결제 완료)에는 주문 상세에서 **취소 사유를 적고 바로 취소**합니다(회원, 비회원 모두). 사유는 관리자 주문 화면·목록·대시보드에 보이고, 고객에게 취소 확인 메일, 관리자(`ADMIN_EMAIL`)에게 사유가 담긴 알림 메일이 갑니다. 배송 준비 중에는 취소 요청, 배송 시작 후에는 반품·교환을 신청합니다.
- 비회원: 상품 상세의 `BUY NOW`로 주문, 이름+휴대전화로 주문 조회(배송지·연락처는 일부 가려서 표시)
- 게시판: 후기(구매한 상품만), Q&A(비밀글), 공지사항
- 전화번호는 입력하면 하이픈(-)이 자동으로 들어갑니다.

**관리자 (`/admin`)**
- 대시보드, 통계(최근 7·30·90일 매출·주문·취소·신규 회원·일별 그래프·인기 상품) 와 엑셀(CSV) 내보내기(주문, 회원, 상품, 취소·반품·교환), 주문/배송 관리(상태·택배사·운송장·고객에게 보이는 메모, 상태 변경 시 이메일 알림), 회원 관리
- 상품 관리: 추가·수정·삭제, 정가·할인율, 대표 이미지 + 추가 이미지 5장(DB 저장), 색상 옵션(최대 8개, 재고는 사이즈별로만 관리), 사이즈별 재고, 품절 처리, WOMEN 기본 + BEST·NEW 표시, 하위 분류
- 후기·문의(답변)·공지 관리, 취소·반품·교환 처리, 쿠폰 만들기, DB 설정

## 규칙

- **할인가**는 정가에서 할인율만큼 자동 계산(10원 단위 아래 버림)하고, 장바구니·주문에 적용됩니다.
- **재고**는 사이즈별(S/M/L)로 관리합니다. 칸을 비우면 무제한, 0이면 품절입니다. 주문이 저장될 때 줄고, 주문을 취소하면 되돌아갑니다.
- **적립금**은 배송 완료 시 결제 금액(배송비 제외)의 1%(`lib/orders.ts`의 `POINT_RATE`)입니다. **쿠폰**은 주문당 1개입니다. 주문을 취소하면 사용한 적립금·쿠폰은 돌아가고 받은 적립금은 회수됩니다.
- **횟수 제한:** 로그인(같은 아이디 5번, 같은 접속지 20번 실패 시 15분), 아이디 찾기, 비밀번호 재설정 메일 요청, 비회원 주문 조회·주문
- **로그인이 필요한 화면**은 `middleware.ts`의 `PROTECTED` 목록(쿠키 확인)과 각 화면의 `requireUser()`/`requireAdmin()`(DB 확인)으로 두 번 확인합니다. 새 보호 화면은 두 곳에 모두 추가하세요.
- 이미지는 올리기 전에 브라우저에서 가로 1200px 이하로 줄이고, 서버는 2MB까지 받습니다. 무료 DB 용량을 쓰므로 사진을 아주 많이 올릴 계획이라면 별도 파일 저장소를 고려하세요.

## 폴더

| 경로 | 설명 |
|---|---|
| `app/` | 화면(페이지)과 서버 동작. `app/admin/`은 관리자, `app/actions/`는 서버 동작, `app/api/`는 이미지 업로드·표시 |
| `components/` | 공통 부품 (헤더, 푸터, 상품 카드, 폼 등) |
| `lib/` | 공통 로직 (DB, 로그인, 가격·할인, 재고, 쿠폰, 주문 처리, 이메일, 횟수 제한, DB 설정 명령 `setup.ts`) |
| `prisma/schema.prisma` | DB 테이블 정의 |
| `prisma/admin-setup.sql` | 처음 한 번, 관리자 계정 만들기 |
| `middleware.ts` | 로그인 필요한 주소의 1차 확인 |
